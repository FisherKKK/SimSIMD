# 整数量化与混合精度计算

> 本文是 SimSIMD 高性能编程讲解系列第九篇。深入解析 i8/u8 量化整数运算、f16/bf16 半精度浮点的 SIMD 实现，以及混合精度计算的精度保证策略。

---

## 一、为什么需要量化？

### 1.1 内存与计算的代价

```
AI 模型向量维度：通常 128~4096 维
向量数量：通常 百万~十亿

以 1M 个 512 维向量为例：
  f64：1M × 512 × 8字节 = 4 GB
  f32：1M × 512 × 4字节 = 2 GB
  f16：1M × 512 × 2字节 = 1 GB
  i8 ：1M × 512 × 1字节 = 512 MB
```

量化的意义不只是省存储：
- **内存带宽**：从内存读取数据的速度是瓶颈，数据越小越快
- **SIMD 并行度**：同样的寄存器宽度，i8 能处理 f32 的 4 倍数量
- **精度损失**：量化有损，但对相似度计算而言损失通常可接受

### 1.2 各类型精度范围

| 类型 | 位宽 | 范围 | 精度（有效数字） |
|------|------|------|----------------|
| f64 | 64位 | ±1.8×10³⁰⁸ | 15-16位十进制 |
| f32 | 32位 | ±3.4×10³⁸ | 7-8位十进制 |
| f16 | 16位 | ±65504 | 3-4位十进制 |
| bf16 | 16位 | ±3.4×10³⁸ | 2-3位十进制 |
| i8 | 8位 | -128 ~ 127 | 整数，无小数 |
| u8 | 8位 | 0 ~ 255 | 整数，无小数 |

## 二、i8 整数点积：最复杂的量化计算

### 2.1 为什么 i8 点积需要特殊处理？

直接的 i8 点积：
```
a = [1, -2, 3, -4]  （i8，范围 -128~127）
b = [5, 6, -7, 8]   （i8，范围 -128~127）

a[0]*b[0] = 1 × 5  = 5
a[1]*b[1] = -2 × 6 = -12
a[2]*b[2] = 3 × -7 = -21
a[3]*b[3] = -4 × 8 = -32

Sum = 5 - 12 - 21 - 32 = -60  ← 超出 i8 范围！（i8 最小只到 -128）
```

**问题1：单个乘积溢出 i8**（-128×-128 = 16384，超出 i8 范围）
**问题2：累加溢出**（512个 i8 的乘积累加，轻易超出 i16 范围）

### 2.2 解决方案：分步提升精度（dot.h Haswell 实现）

```c
// dot.h 第 1155-1177 行
// 策略：i8 → i16 → i32 逐步升精度

__m256i ab_i32_low_vec  = _mm256_setzero_si256();  // i32 累加器（低半）
__m256i ab_i32_high_vec = _mm256_setzero_si256();  // i32 累加器（高半）

for (; idx_scalars + 32 <= count_scalars; idx_scalars += 32) {
    // 步骤1：加载 32 个 i8
    __m256i a_i8_vec = _mm256_lddqu_si256((__m256i const *)(a_scalars + idx_scalars));
    __m256i b_i8_vec = _mm256_lddqu_si256((__m256i const *)(b_scalars + idx_scalars));

    // 步骤2：把 32个i8 拆成两组，每组 16个i8 → 16个i16
    // extracti128：取 256位寄存器的低128位或高128位
    // cvtepi8_epi16：i8 → i16（符号扩展）
    __m256i a_i16_low  = _mm256_cvtepi8_epi16(_mm256_extracti128_si256(a_i8_vec, 0)); // 低16个
    __m256i a_i16_high = _mm256_cvtepi8_epi16(_mm256_extracti128_si256(a_i8_vec, 1)); // 高16个
    __m256i b_i16_low  = _mm256_cvtepi8_epi16(_mm256_extracti128_si256(b_i8_vec, 0));
    __m256i b_i16_high = _mm256_cvtepi8_epi16(_mm256_extracti128_si256(b_i8_vec, 1));

    // 步骤3：madd_epi16：
    // 对相邻的 i16 对，计算乘积并相加，结果为 i32
    // [a0*b0+a1*b1, a2*b2+a3*b3, ...] （每对 2个i16 → 1个i32）
    // 这是 AVX2 里最高效的整数点积方式！
    ab_i32_low_vec  = _mm256_add_epi32(ab_i32_low_vec,  _mm256_madd_epi16(a_i16_low,  b_i16_low));
    ab_i32_high_vec = _mm256_add_epi32(ab_i32_high_vec, _mm256_madd_epi16(a_i16_high, b_i16_high));
}

// 最终规约
int ab = _simsimd_reduce_i32x8_haswell(_mm256_add_epi32(ab_i32_low_vec, ab_i32_high_vec));
```

### 2.3 `_mm256_madd_epi16` 的威力

`_mm256_madd_epi16` 是 AVX2 中最"合算"的整数指令之一：

```
输入：a = [a0, a1, a2, a3, a4, a5, a6, a7, ...]  （16个i16）
     b = [b0, b1, b2, b3, b4, b5, b6, b7, ...]  （16个i16）

输出：[a0*b0+a1*b1, a2*b2+a3*b3, a4*b4+a5*b5, a6*b6+a7*b7, ...] （8个i32）

一条指令：16次乘法 + 8次加法 = 24次运算！
```

**对比朴素方法**：如果每次做1个乘法，需要16条指令。

### 2.4 u8 点积：unpack vs extract 的差异

`dot.h` 第 1179-1211 行展示了 u8 和 i8 的不同处理方式：

```c
// u8 版本：使用 unpack 而不是 extract + cvtepi8
// 注释说："Unlike the signed version, we can use the unpacking
// instructions instead of extracts, as they are much faster and more efficient."

__m256i const zeros_vec = _mm256_setzero_si256();

for (...) {
    __m256i a_u8_vec = _mm256_lddqu_si256(...);
    __m256i b_u8_vec = _mm256_lddqu_si256(...);

    // unpacklo_epi8：把低16个 u8 与 0 交织，得到16个 u16
    // [a0, 0, a1, 0, a2, 0, ...] 重新解释为 [a0, a1, a2, ...]（16位）
    __m256i a_i16_low  = _mm256_unpacklo_epi8(a_u8_vec, zeros_vec);
    __m256i a_i16_high = _mm256_unpackhi_epi8(a_u8_vec, zeros_vec);
    // 同理 b...

    ab_i32_low_vec  = _mm256_add_epi32(ab_i32_low_vec,  _mm256_madd_epi16(a_i16_low,  b_i16_low));
    ab_i32_high_vec = _mm256_add_epi32(ab_i32_high_vec, _mm256_madd_epi16(a_i16_high, b_i16_high));
}
```

**为什么 u8 用 unpack 更快？**

`_mm256_extracti128_si256` + `_mm256_cvtepi8_epi16` 需要两条指令，且 extract 有额外的延迟。
`_mm256_unpacklo_epi8(x, zeros)` 一条指令直接实现零扩展，且 unpack 的吞吐量更高。

这是一个**具体 CPU 微架构知识**影响代码选择的典型例子。

## 三、ARM NEON 的 vdotq：专为量化设计的指令

ARM v8.4 引入了 `vdotq_s32`（dotprod 扩展），专门加速 i8 量化计算：

```c
// spatial.h 第 712-733 行（ARM NEON i8 余弦距离）
int32x4_t ab_vec = vdupq_n_s32(0);  // 4个i32的累加器
int32x4_t a2_vec = vdupq_n_s32(0);
int32x4_t b2_vec = vdupq_n_s32(0);

for (; i + 16 <= n; i += 16) {
    int8x16_t a_vec = vld1q_s8(a + i);  // 16个i8
    int8x16_t b_vec = vld1q_s8(b + i);

    // vdotq_s32：把16个i8看作4组（每组4个）
    // 每组：a[0]*b[0] + a[1]*b[1] + a[2]*b[2] + a[3]*b[3] → i32
    // 结果：4个i32累加到累加器
    ab_vec = vdotq_s32(ab_vec, a_vec, b_vec);  // 16次乘法+12次加法，一条指令！
    a2_vec = vdotq_s32(a2_vec, a_vec, a_vec);
    b2_vec = vdotq_s32(b2_vec, b_vec, b_vec);
}
```

**vdotq 的内部工作**：

```
输入：a = [a0, a1, a2, a3 | a4, a5, a6, a7 | a8, a9, a10, a11 | a12, a13, a14, a15]
      b = [b0, b1, b2, b3 | b4, b5, b6, b7 | b8, b9, b10, b11 | b12, b13, b14, b15]

输出累加器中的4个通道：
  channel[0] += a0*b0 + a1*b1 + a2*b2 + a3*b3
  channel[1] += a4*b4 + a5*b5 + a6*b6 + a7*b7
  channel[2] += a8*b8 + a9*b9 + a10*b10 + a11*b11
  channel[3] += a12*b12 + a13*b13 + a14*b14 + a15*b15
```

## 四、vabdq：绝对差值的巧妙用法

SimSIMD 在计算 L2 距离时用了一个非直观的技巧（spatial.h 第 599-613 行）：

```c
// i8 L2 距离
uint32x4_t d2_vec = vdupq_n_u32(0);
for (; i + 16 <= n; i += 16) {
    int8x16_t a_vec = vld1q_s8(a + i);
    int8x16_t b_vec = vld1q_s8(b + i);

    // vabdq_s8：计算 |a - b|（绝对差值），结果用 int8 存储
    // 注意：结果是 signed，但实际值是 0~255（非负）
    // 所以可以 reinterpret 成 uint8 来用 vdotq_u32（点积到 uint32）
    uint8x16_t d_vec = vreinterpretq_u8_s8(vabdq_s8(a_vec, b_vec));

    // d_vec * d_vec = |a-b|²，用 vdotq 累加到 uint32
    d2_vec = vdotq_u32(d2_vec, d_vec, d_vec);
}
```

**性能注释**（spatial.h 第 592-598 行，作者原话）：
```
朴素方法（i8→i16→subtract→multiply→i32）：17 GB/s
vabdq_s8 方法：33 GB/s（+94%）
（vdotq 方法：39 GB/s，如果也加 dotprod 扩展）
```

**为什么 vabdq 快？**
- `vabdq_s8` 是一条专用指令，计算 16 个 `|a[i]-b[i]|`，比手工减法+符号处理快
- `vreinterpretq_u8_s8` 是零代价的（编译器不生成任何指令，只改变类型解释）
- 把 signed i8 结果当 unsigned u8 用，再用 `vdotq_u32`（无符号点积）计算平方和

## 五、f16（半精度）的软件与硬件路径

### 5.1 没有原生 f16 支持时的软件转换

`types.h` 中实现了完整的 f16 ↔ f32 软件转换（第 551-590 行）：

```c
// f16 → f32：利用 IEEE 754 格式的位布局
SIMSIMD_INTERNAL simsimd_f32_t simsimd_f16_to_f32_implementation(simsimd_f16_t const *x_ptr) {
    unsigned short x;
    SIMSIMD_COPY16(&x, x_ptr);  // 读取16位

    // IEEE 754 f16 格式：[sign(1)] [exponent(5)] [mantissa(10)]
    unsigned int exponent = (x & 0x7C00) >> 10;  // 提取5位指数
    unsigned int mantissa = (x & 0x03FF) << 13;  // 提取10位尾数，扩展到f32位置

    simsimd_f32i32_t mantissa_conv;
    mantissa_conv.f = (float)mantissa;  // 借助浮点乘法找到尾数的实际值
    unsigned int v = (mantissa_conv.i) >> 23;  // 提取它的指数偏置

    // 重构 f32：处理正规数、次正规数和特殊值（Inf/NaN）
    simsimd_f32i32_t conv;
    conv.i = (x & 0x8000) << 16                              // 符号位
           | (exponent != 0) * ((exponent + 112) << 23 | mantissa) // 正规数：调整指数偏置（127-15=112）
           | ((exponent == 0) & (mantissa != 0))              // 次正规数
             * ((v - 37) << 23 | ((mantissa << (150 - v)) & 0x007FE000));
    return conv.f;
}
```

**f16 指数偏置**：f16 使用偏置 15（exponent - 15 = 实际指数），f32 使用偏置 127。转换时需加 127-15=112。

### 5.2 有原生 f16 时：AVX2 的 F16C 扩展

```c
// dot.h 第 1030-1050 行（Haswell f16 点积）
// _mm256_cvtph_ps：一条指令把 8个f16 转换为 8个f32
// 这比软件转换快约10~100倍！

simsimd_dot_f16_haswell_cycle:
    if (count_scalars < 8) {
        a_vec = _mm256_cvtph_ps(_simsimd_partial_load_f16x8_haswell(a_scalars, count_scalars));
        b_vec = _mm256_cvtph_ps(_simsimd_partial_load_f16x8_haswell(b_scalars, count_scalars));
        count_scalars = 0;
    }
    else {
        // _mm_lddqu_si128：加载 128位（8个f16 = 16字节）
        a_vec = _mm256_cvtph_ps(_mm_lddqu_si128((__m128i const *)a_scalars));
        b_vec = _mm256_cvtph_ps(_mm_lddqu_si128((__m128i const *)b_scalars));
        a_scalars += 8, b_scalars += 8, count_scalars -= 8;
    }
    // 在 f32 精度下计算
    ab_vec = _mm256_fmadd_ps(a_vec, b_vec, ab_vec);
    if (count_scalars) goto simsimd_dot_f16_haswell_cycle;
```

**处理流程**：
```
内存中的 f16 → _mm_lddqu_si128（加载128位）→ _mm256_cvtph_ps（转f32）→ FMA 计算
```

### 5.3 bf16（脑浮点）的更简单转换

bf16 和 f32 的关系极其简单：

```
f32 的位布局：[sign(1)] [exponent(8)] [mantissa(23)]
bf16 的位布局：[sign(1)] [exponent(8)] [mantissa(7)]

bf16 就是把 f32 的低 16 位截掉！
```

```c
// dot.h 第 1213-1215 行（Haswell bf16 → f32，一行搞定）
SIMSIMD_INTERNAL __m256 _simsimd_bf16x8_to_f32x8_haswell(__m128i x) {
    // 把 8个bf16（存在128位寄存器里）扩展为 8个i32，再左移16位
    // 左移16位 = 把低16位变成高16位，低16位填0
    // 结果恰好就是 f32！
    return _mm256_castsi256_ps(_mm256_slli_epi32(_mm256_cvtepu16_epi32(x), 16));
}
```

**bf16 → f32 只需要两条指令**！相比 f16 转换需要的位操作处理（次正规数、特殊值等），bf16 简单得多。

### 5.4 f32 → bf16 的截断（带舍入）

```c
// dot.h 第 1218-1240 行
SIMSIMD_INTERNAL __m128i _simsimd_f32x8_to_bf16x8_haswell(__m256 x) {
    // 截断低16位：不是直接 shift right，而是先 shuffle 再 pack
    // 原因：_mm256_shuffle_epi8 可以直接取每个4字节中的高2字节

    // 对每个 f32，取字节 [2, 3]（高16位），扔掉 [0, 1]（低16位）
    __m256i trunc_elements = _mm256_shuffle_epi8(
        _mm256_castps_si256(x),
        _mm256_set_epi8(
            -1, -1, 15, 14,   // 取第8个f32的高2字节
            -1, -1, 11, 10,   // 取第7个f32的高2字节
            // ... 共8个
        )
    );
    // 把256位里的8个"分散"的 bf16 值打包到128位寄存器
    __m256i t = _mm256_permute4x64_epi64(trunc_elements, 0x58);
    return _mm256_castsi256_si128(t);
}
```

## 六、混合精度的积累策略

SimSIMD 的一个重要设计决策是**累加器的精度选择**：

```c
// 典型模式（spatial.h，余弦距离 f16 输入）：

// 输入：f16（16位）
// 转换：f16 → f32（在循环体内，每次处理）
// 累加：f32（4个 f32 的 NEON 向量）
// 规约：f32 → f64（水平求和时升精度）
// 输出：f64（最终距离值）
```

**这个四级精度链的理由**：

| 阶段 | 精度 | 理由 |
|------|------|------|
| 输入 | f16 | 节省内存，AI 模型常用 |
| 计算 | f32 | f16 直接相乘会溢出/损失精度 |
| 累加 | f32 | 每次累加量级类似，f32 足够 |
| 规约 | f64 | 数百个 f32 相加，f32 精度不够 |
| 输出 | f64 | 接口统一，调用者不损失精度 |

## 七、i4x2：4位整数的打包方案

SimSIMD 还支持 `i4x2`（两个4位整数打包在一个字节里）：

```c
// types.h 中的 simsimd_datatype_i4x2_k
// 格式：高4位存第一个值，低4位存第二个值

// 打包：
uint8_t packed = ((high & 0xF) << 4) | (low & 0xF);

// 解包：
int8_t high = (packed >> 4) & 0xF;  // 符号扩展：如果 > 7，变负数
int8_t low  = (packed & 0xF);
```

这进一步把存储压缩了一倍（相比 i8），用于极度受内存约束的场景（如移动端 AI）。

## 八、精度损失的可接受性分析

**关键问题**：量化导致的精度损失，对相似度搜索的最终结果有多大影响？

理论分析：
```
如果原始余弦距离是 0.1234567，
  f32 存储：0.1234567（约7位有效数字）
  f16 存储：0.1235（约4位有效数字）
  i8 量化后：误差约 1-2%

对于"前10名最相似向量"的搜索：
  如果第10名和第11名的距离差 > 量化误差（通常成立），结果不变
  如果边界情况（距离非常接近的两个向量），顺序可能变化
```

在实际 AI 应用中，i8 量化对最终搜索质量（recall@k）的影响通常 < 1%，但速度提升 4 倍。这就是为什么向量数据库大量采用量化技术。

## 九、小结

| 量化类型 | 对应 SIMD 指令 | 关键技术 |
|---------|--------------|---------|
| i8 点积 | `_mm256_madd_epi16` | i8→i16→madd→i32 |
| u8 点积 | `_mm256_unpacklo/hi_epi8` + madd | 零扩展而不是符号扩展 |
| ARM i8 | `vdotq_s32` | 专用点积指令（dotprod） |
| f16 | `_mm256_cvtph_ps` | F16C 扩展，硬件转换 |
| bf16 | `_mm256_cvtepu16_epi32` + shift | 简单移位，2条指令 |
| 混合精度 | f16→f32→f64 链 | 计算时升精度，存储时降精度 |
| i4x2 | 位操作打包/解包 | 最极限的压缩 |
