# 矩阵运算与曲面空间度量：BLAS 级别的 SIMD 优化

> 本文是 SimSIMD 高性能编程讲解系列第十五篇。讲解 `curved.h` 中的双线性形式（Bilinear Form）和 Mahalanobis 距离的实现——涉及向量-矩阵乘法、运算顺序重排、内存访问优化等 BLAS 级别的设计决策。

---

## 一、什么是曲面空间度量？

### 1.1 普通欧氏距离的局限

普通 L2 距离假设各维度相互独立且等权重：

```
L2(a, b) = √(Σ (a[i] - b[i])²)
```

但在现实中，数据各维度之间往往有**相关性**。例如：

```
身高（cm）和体重（kg）的相关性：
  如果我们说"这两个人的差距"，身高差10cm和体重差10kg哪个更显著？
  欧氏距离无法回答这个问题——需要考虑各维度的方差和协方差。

Mahalanobis 距离正是解决这个问题的：
  d_M(a, b) = √((a-b)ᵀ · C⁻¹ · (a-b))
  其中 C 是协方差矩阵，C⁻¹ 是其逆矩阵
```

### 1.2 双线性形式

比 Mahalanobis 更一般的形式是**双线性形式（Bilinear Form）**：

```
bilinear(a, b, C) = aᵀ · C · b
                  = Σᵢ Σⱼ a[i] × C[i][j] × b[j]

特殊情况：
  当 a = b 且 C 是单位矩阵：bilinear = aᵀ·I·a = |a|² （点积）
  当 a = b 且 C = C⁻¹（协方差逆）：bilinear = Mahalanobis²
```

### 1.3 SimSIMD 的实现范围

```
curved.h 支持的操作：
  simsimd_bilinear_*        → aᵀ · C · b（双线性形式）
  simsimd_mahalanobis_*     → √((a-b)ᵀ · C · (a-b))

数据类型：f64, f32, f16, bf16（及各自的复数版本）
后端：serial, NEON, Haswell, Skylake, Genoa, Sapphire
```

## 二、朴素实现的性能问题

### 2.1 直接展开的代价

最直观的实现：

```c
// 朴素双线性形式（O(n²) 时间，O(1) 空间）
double result = 0;
for (int i = 0; i < n; i++) {
    for (int j = 0; j < n; j++) {
        result += a[i] * C[i][j] * b[j];
    }
}
```

**内存访问分析**：

```
每次内层循环迭代：
  读 a[i]：可以缓存（外层循环一次读取，内层循环 n 次复用）
  读 C[i][j]：按行顺序访问，对缓存友好（顺序）
  读 b[j]：按顺序访问，对缓存友好

但是：
  a[i] 在内层循环中是标量，每次迭代重新读取——这是冗余的！
  改进：把 a[i] 提升为常量，内层循环只用矩阵 C 和向量 b
```

### 2.2 运算顺序重排：利用结合律

关键洞察（来自 `curved.h` 第 22-30 行注释）：

```
矩阵乘法是结合的：(A × B) × C = A × (B × C)

对于 bilinear = aᵀ × C × b：

策略1（按行处理，低效）：
  对每个 i：
    计算 row_i = aᵀ[i] × C[i, :]（向量）
    然后 row_i · b（点积）

策略2（按列内积，SimSIMD 的做法）：
  对每个 j：
    计算 col_j = C[:, j] · a（点积，得到标量）
    累加：result += col_j × b[j]

但 SimSIMD 实际用的是更智能的策略3（见下节）
```

### 2.3 SimSIMD 的策略：最大化算术强度

```c
// curved.h 第 221-248 行（bilinear_f32_neon）
SIMSIMD_PUBLIC void simsimd_bilinear_f32_neon(
    simsimd_f32_t const *a, simsimd_f32_t const *b, simsimd_f32_t const *c, // c 是矩阵 C
    simsimd_size_t n, simsimd_distance_t *result) {

    float32x4_t sum_vec = vdupq_n_f32(0);  // 外层累加器

    for (simsimd_size_t i = 0; i != n; ++i) {
        // a[i] 是标量，广播到向量寄存器（外层循环只读一次 a[i]）
        float32x4_t a_vec = vdupq_n_f32(a[i]);    // 广播 a[i]
        float32x4_t cb_j_vec = vdupq_n_f32(0);    // 内层累加器

        // 内层循环：向量化计算 C[i, :] · b[:]
        for (simsimd_size_t j = 0; j + 4 <= n; j += 4) {
            float32x4_t b_vec = vld1q_f32(b + j);          // 加载 b[j..j+3]
            float32x4_t c_vec = vld1q_f32(c + i * n + j);  // 加载 C[i, j..j+3]
            cb_j_vec = vmlaq_f32(cb_j_vec, b_vec, c_vec);  // cb_j += C[i,j..j+3] * b[j..j+3]
        }

        // 内层归约后，外层乘以 a[i]
        // a_vec × cb_j_vec 是 4 个独立的计算（a[i] 广播到所有 lane）
        sum_vec = vmlaq_f32(sum_vec, a_vec, cb_j_vec);
    }

    // 水平归约：4 个 float → 1 个 double
    simsimd_f64_t sum = vaddvq_f32(sum_vec);

    // 处理尾部（n 不是 4 的倍数时）
    simsimd_size_t const tail_length = n % 4;
    simsimd_size_t const tail_start = n - tail_length;
    if (tail_length) {
        for (simsimd_size_t i = 0; i != n; ++i) {
            simsimd_f32_t a_i = a[i];
            simsimd_f32_t cb_j = 0;
            for (simsimd_size_t j = tail_start; j != n; ++j)
                cb_j += b[j] * c[i * n + j];
            sum += a[i] * cb_j;
        }
    }
    *result = sum;
}
```

## 三、内存访问模式分析

### 3.1 矩阵 C 的访问模式

```
矩阵 C 是 n×n，按行存储（Row-Major）：
  C[i][j] 在内存地址 = &C[0][0] + i*n + j

内层循环 for j 的访问：
  j=0: C[i][0], C[i][1], C[i][2], C[i][3]（连续 16 字节）
  j=4: C[i][4], C[i][5], C[i][6], C[i][7]（连续）
  → 顺序访问，非常友好于缓存预取器！

外层循环 for i 的访问：
  每次 i 递增，访问矩阵的下一行
  C[i][j] → C[i+1][j]：跳跃了整行（n × 4字节）
  → 行切换时，可能有缓存行失效（如果 n 很大）

现实中 n 通常不大（几百到几千维），整个矩阵 n×n×4 字节：
  n=128：64KB ≈ 2× L1 缓存（可能有 L1 压力）
  n=32： 4KB  < L1（全部缓存）
```

### 3.2 向量 b 的访问：内层循环的关键

```
内层循环中，b[j] 被访问 n 次（外层每次 i 迭代都重新访问 b）：

第一次 i=0：b[0..n-1] 全部加载到缓存
第二次 i=1：b[0..n-1] 很可能还在缓存中！
...
第 n 次 i=n-1：b 几乎全程在缓存中

这是极好的**数据复用**：b 加载一次，被重复使用 n 次。
算术强度 = n × 2n（FLOP）/ (n² + 2n)（字节）≈ 2 FLOP/byte（远好于点积！）
```

### 3.3 为什么 `vdupq_n_f32(a[i])` 在外层？

```c
// 内层循环中不读 a，只用 a_vec（已广播的常量）
float32x4_t a_vec = vdupq_n_f32(a[i]);    // 外层：只读 1 次

for (j = ...) {
    // 内层：不读 a，直接用寄存器 a_vec
    cb_j_vec = vmlaq_f32(cb_j_vec, b_vec, c_vec);
}
sum_vec = vmlaq_f32(sum_vec, a_vec, cb_j_vec);  // 外层：用广播的 a_vec
```

**如果 a[i] 在内层循环里读取**：
- 每次 j 迭代都重新读取相同的 a[i]
- 增加了不必要的内存访问（或至少增加了 load 指令数量）
- 阻止了编译器的某些优化

**广播到寄存器**后，整个内层循环（n/4 次迭代）都使用同一个寄存器，零内存开销。

## 四、Mahalanobis 距离的实现

### 4.1 数学推导

```
Mahalanobis 距离：
  d_M(a, b) = √((a-b)ᵀ · C · (a-b))

设 diff = a - b，则：
  d_M² = diffᵀ · C · diff
       = Σᵢ Σⱼ diff[i] × C[i][j] × diff[j]

这正是以 diff 为"向量"的双线性形式！

SimSIMD 的策略：
  不单独计算 diff 向量，而是在循环中动态计算差值
```

### 4.2 代码实现（NEON，`curved.h` 第 251-282 行）

```c
SIMSIMD_PUBLIC void simsimd_mahalanobis_f32_neon(
    simsimd_f32_t const *a, simsimd_f32_t const *b, simsimd_f32_t const *c,
    simsimd_size_t n, simsimd_distance_t *result) {

    float32x4_t sum_vec = vdupq_n_f32(0);

    for (simsimd_size_t i = 0; i != n; ++i) {
        // diff_i = a[i] - b[i]，广播（只在外层计算一次）
        float32x4_t diff_i_vec = vdupq_n_f32(a[i] - b[i]);
        float32x4_t cdiff_j_vec = vdupq_n_f32(0);

        for (simsimd_size_t j = 0; j + 4 <= n; j += 4) {
            // diff_j = a[j..j+3] - b[j..j+3]（向量化差值）
            float32x4_t diff_j_vec = vsubq_f32(vld1q_f32(a + j), vld1q_f32(b + j));
            float32x4_t c_vec = vld1q_f32(c + i * n + j);
            // 累加：C[i][j] × diff[j]
            cdiff_j_vec = vmlaq_f32(cdiff_j_vec, diff_j_vec, c_vec);
        }
        // 外层：diff[i] × (Σⱼ C[i][j] × diff[j])
        sum_vec = vmlaq_f32(sum_vec, diff_i_vec, cdiff_j_vec);
    }

    simsimd_f64_t sum = vaddvq_f32(sum_vec);
    // 尾部处理...
    *result = _simsimd_sqrt_f64_neon(sum);  // 最后才开方！
}
```

**关键优化：避免临时 diff 数组**

```
朴素实现：
  1. 分配 diff[n] 数组
  2. 计算 diff[i] = a[i] - b[i]（N次写）
  3. 计算双线性形式（N²次读 diff + N²次读 C）

优化实现：
  1. 不分配 diff 数组！
  2. 外层：动态计算 a[i]-b[i]（标量）
  3. 内层：动态计算 a[j..j+3]-b[j..j+3]（向量，与读 C 交错）

节省：
  - 减少了一次 O(N) 内存分配和写入
  - a 和 b 在内循环中顺序访问，缓存友好
  - diff 不写到内存，直接在寄存器中使用（零延迟）
```

### 4.3 为什么最后才开平方？

```c
// 全部计算完，最后才调用 sqrt：
*result = _simsimd_sqrt_f64_neon(sum);

// 注意：sum 此时是 Mahalanobis 距离的平方！

// sqrt 非常昂贵：约 10-20 个周期（精确值）
// 但每次调用 mahalanobis 只需要一次 sqrt（在最后）
// 对比：如果中间步骤需要 sqrt，那就需要 N 次——避免了 N-1 次！

// 同理，spatial.h 的 SIMSIMD_MAKE_L2 宏：
//   SIMSIMD_MAKE_L2SQ 计算平方距离
//   SIMSIMD_MAKE_L2 调用 L2SQ 后才开方
//   如果只需要比较大小（找最近邻），可以只用 L2SQ，完全不开方！
```

## 五、复数双线性形式

### 5.1 复数矩阵乘法

对于复数向量 a, b 和复数矩阵 C：

```
bilinear_complex(a, b, C) = aᵀ · C · b

每个元素是复数乘法：
  (ar + i·ai) × (Cr + i·Ci) × (br + i·bi)
  = 复杂的实虚部交叉项

实部：ar·Cr·br - ar·Ci·bi - ai·Cr·bi - ai·Ci·br
虚部：ar·Cr·bi + ar·Ci·br + ai·Cr·br - ai·Ci·bi
```

### 5.2 `vld2q_f32` 的解交织加载

```c
// curved.h 第 294-307 行（bilinear_f32c_neon 内层循环）

// 内存中的复数数组（交织存储）：
// b = [br0, bi0, br1, bi1, br2, bi2, br3, bi3]（8个float，4个复数）

// vld2q_f32：解交织加载！
// 把交织的 [r, i, r, i, r, i, r, i] 分成两个寄存器：
//   .val[0] = [br0, br1, br2, br3]（所有实部）
//   .val[1] = [bi0, bi1, bi2, bi3]（所有虚部）
float32x4x2_t b_vec = vld2q_f32((simsimd_f32_t const *)(b + j));
float32x4x2_t c_vec = vld2q_f32((simsimd_f32_t const *)(c + i * n + j));

float32x4_t b_real_vec = b_vec.val[0];
float32x4_t b_imag_vec = b_vec.val[1];
float32x4_t c_real_vec = c_vec.val[0];
float32x4_t c_imag_vec = c_vec.val[1];

// 复数乘法 C[i,j] × b[j]（对 4 个复数同时）：
// (Cr + i·Ci) × (br + i·bi) = (Cr·br - Ci·bi) + i·(Cr·bi + Ci·br)
cb_j_real_vec = vfmaq_f32(cb_j_real_vec, c_real_vec, b_real_vec);  // += Cr×br
cb_j_real_vec = vfmsq_f32(cb_j_real_vec, c_imag_vec, b_imag_vec);  // -= Ci×bi
cb_j_imag_vec = vfmaq_f32(cb_j_imag_vec, c_real_vec, b_imag_vec);  // += Cr×bi
cb_j_imag_vec = vfmaq_f32(cb_j_imag_vec, c_imag_vec, b_real_vec);  // += Ci×br
```

**`vld2q_f32` vs 手动 Shuffle 的比较**：

```
vld2q_f32（ARM 专用）：
  一条指令，解交织 8 个 float（4 实 + 4 虚）
  延迟：约 5 周期（内存延迟），硬件解交织
  吞吐量：每 2 周期 1 条（与普通 vld1q 几乎相同）

x86 等效（无专用指令）：
  需要：vunpcklps + vunpckhps + vperm（2-3 条指令）
  延迟：约 3-6 周期（纯 shuffle 延迟）

ARM 的 vld2/vld3/vld4 系列：
  数据加载和解交织合并为单条指令
  在向量化 DSP（信号处理）、图像处理（RGB分量）、复数运算中非常有用
```

## 六、尾部处理的精细设计

### 6.1 双层嵌套循环的尾部问题

双线性形式是 O(n²) 的，尾部处理比一维情况更复杂：

```c
// curved.h 第 235-246 行（bilinear_f32_neon 尾部）

// 计算 n 对 4 的余数
simsimd_size_t const tail_length = n % 4;  // 0, 1, 2, or 3
simsimd_size_t const tail_start = n - tail_length;

if (tail_length) {
    for (simsimd_size_t i = 0; i != n; ++i) {
        simsimd_f32_t a_i = a[i];
        simsimd_f32_t cb_j = 0;
        // 只处理每行的尾部（tail_start 到 n-1）
        for (simsimd_size_t j = tail_start; j != n; ++j)
            cb_j += b[j] * c[i * n + j];
        sum += a[i] * cb_j;
    }
}
```

**设计要点**：

```
SIMD 主循环处理了 [0, tail_start) 范围内的 j
尾部标量循环处理 [tail_start, n) 范围内的 j
两部分结果在 sum 变量中累加（SIMD 结果先归约到标量，再加尾部）

注意：外层 i 循环仍然完整地跑 0 到 n-1
      但每次只补充 j 的尾部（最多 3 个元素）
      这是最小化代码复杂度同时保证正确性的设计
```

## 七、算术强度总结

| 操作 | FLOP/字节 | 受限因素 | 优化方向 |
|------|----------|---------|---------|
| 点积 f32 | 0.25 | 内存带宽 | 量化（f16/i8） |
| 双线性 f32 | ~2 | 计算（FMA） | 多累加器、指令级并行 |
| Mahalanobis f32 | ~2 | 计算 | 避免临时数组 |
| elementwise wsum | 0.5 | 内存带宽（写密集） | 对齐写、缓存行优化 |

**双线性形式和 Mahalanobis 是计算密集型的**，原因是数据（特别是向量 b）被大量复用：b 的每个元素参与了 n 次计算（对每一行 i）。这使得算术强度远高于点积。
