## 一、近似计算：速度与精度的权衡艺术

### 1.1 快速倒数平方根（Quake III 的遗产）

`types.h` 中实现了著名的"快速倒数平方根"：

```c
// types.h 第 508-515 行
SIMSIMD_INTERNAL simsimd_f32_t simsimd_approximate_inverse_square_root(simsimd_f32_t number) {
    simsimd_f32i32_t conv;
    conv.f = number;
    // 魔法数字：使用 Jan Kadlec 优化的版本（比 Quake 3 原版更精确）
    conv.i = 0x5F1FFFF9 - (conv.i >> 1);
    // Newton-Raphson 精化
    conv.f *= 0.703952253f * (2.38924456f - number * conv.f * conv.f);
    return conv.f;
}
```

**原理分解**：

```
原始问题：计算 1/√x，避免使用 sqrtf() + 除法（很慢）

步骤1：位操作技巧
  对于 IEEE 754 浮点数 x = 2^e × m（e是指数，m是尾数）：
  log₂(x) ≈ e + m - 127  （整数近似）

  所以 log₂(1/√x) = -½ × log₂(x)

  整数右移1位 ≈ 除以2（对log近似值适用）
  conv.i = magic - (conv.i >> 1)  →  得到 1/√x 的粗略近似

步骤2：Newton-Raphson 精化
  设 y = 当前近似值，则精确值满足：f(y) = 1/y² - x = 0
  迭代：y_{n+1} = y_n × (1.5 - 0.5 × x × y_n²)
  一次迭代后误差 < 0.2%，对相似度计算足够精确

Quake 3 的魔法数字：0x5F3759DF（1999年）
Jan Kadlec 优化版：0x5F1FFFF9（2010年，更小误差）
```

**历史背景**：这个算法最初出现在 Quake III Arena（1999年）的图形渲染代码中，由 John Carmack 发布。注释中指出：
- 2009年的 Intel Core 2 测试：SSE `rsqrtss` 指令需要 0.85ns，这个算法需要 3.54ns
- 所以在有 SIMD 支持时，直接用硬件指令；没有时，用这个近似

### 1.2 近似对数（Mercator 级数）

```c
// types.h 第 534-539 行
SIMSIMD_INTERNAL simsimd_f32_t simsimd_approximate_log(simsimd_f32_t number) {
    simsimd_f32_t x = number - 1;
    simsimd_f32_t x2 = x * x;
    simsimd_f32_t x3 = x * x * x;
    return x - x2 / 2 + x3 / 3;  // ln(1+x) ≈ x - x²/2 + x³/3 ...
}
```

这是 Mercator 级数（1668年！）的前三项：
```
ln(1+x) = x - x²/2 + x³/3 - x⁴/4 + ...  （|x| < 1 时收敛）
```

**适用场景**：串行实现中，用这个代替 `logf()`，避免依赖 LibC（标准 C 库）。

### 1.3 精度与性能的决策矩阵

| 场景 | 选择 | 原因 |
|------|------|------|
| SIMD 可用时 | 硬件 RSQRT 指令 | 更精确（误差0.0094%）且更快 |
| 无 SIMD 时 | Quake 近似法 | 比 `sqrtf()`+`1/` 快4倍 |
| 需要高精度 | `_accurate` 变体 | 用 f64 累加 |
| KL/JS 散度 | Horner 多项式 | 避免 LibC 依赖 |
| NEON log | 指数分离+多项式 | 向量化log₂ |

## 二、稀疏向量的 Galloping 算法

`sparse.h` 中实现了一个非常有趣的算法：

### 2.1 朴素集合求交（Two-Pointer）

```c
// 标准双指针算法
// 假设 a 和 b 都是已排序的整数数组
size_t intersection_size = 0;
size_t i = 0, j = 0;
while (i < a_length && j < b_length) {
    if (a[i] == b[j]) {
        intersection_size++;
        i++; j++;
    } else if (a[i] < b[j]) {
        i++;  // a 落后，推进 a
    } else {
        j++;  // b 落后，推进 b
    }
}
```

**时间复杂度**：O(m + n)，m 和 n 是两个数组的长度。

### 2.2 Galloping（跳跃搜索）

当两个数组大小差异悬殊时（例如一个很长，一个很短），双指针仍然是 O(m + n)，但实际上可以做得更好：

```c
// 稀疏向量注释（sparse.h 第 23-44 行）
// Galloping 思路：如果 a 落后太多，不是一步一步追，
// 而是像"奔跑（gallop）"一样：跳1, 2, 4, 8, 16... 步，
// 直到超过目标，然后二分查找找到确切位置

void gallop_to(array, start, target) {
    step = 1;
    while (array[start + step] < target) {
        step *= 2;  // 步长翻倍（指数增长）
    }
    // 在 [start + step/2, start + step] 范围内二分查找
    binary_search(array, start + step/2, start + step, target);
}
```

**时间复杂度**：O(m × log(n/m))，当 m << n 时，比 O(m + n) 快得多。

**打比方**：找一个比你跑得快很多的人——不要一步步追，先大步追上，再微调位置。

### 2.3 AVX512 VP2INTERSECT（Turin 特有）

AMD Turin CPU 提供了专门用于集合求交的硬件指令：

```c
// sparse.h 中的 Turin 后端
// _mm512_2intersect_epi32：同时处理两个 16 元素的 32 位整数集合
// 返回两个掩码：指出哪些元素匹配
__m512i va = _mm512_loadu_epi32(a + i);
__m512i vb = _mm512_loadu_epi32(b + j);
__mmask16 ma, mb;
_mm512_2intersect_epi32(va, vb, &ma, &mb);
// ma：a 中哪些元素在交集里
// mb：b 中哪些元素在交集里
```

一条指令处理 16×16 = 256 对比较，比软件实现快几十倍。

## 三、内存访问优化

### 3.1 缓存友好性

SimSIMD 的所有算法都假设**顺序访问**内存（Sequential Access）：

```c
// 好：顺序访问，对 CPU 缓存预取器友好
for (i = 0; i + 4 <= n; i += 4) {
    float32x4_t a_vec = vld1q_f32(a + i);  // a[i..i+3]
    float32x4_t b_vec = vld1q_f32(b + i);  // b[i..i+3]
    // ...
}

// 坏：随机访问（不是 SimSIMD 的模式）
for each index in random_order {
    result += a[index] * b[index];  // 缓存 miss 频繁
}
```

**为什么顺序访问快？** CPU 有硬件预取器，检测到顺序访问模式后，会提前把下一批数据从内存加载到缓存，使实际数据访问时缓存已经命中。

### 3.2 数据对齐

虽然 SimSIMD 使用非对齐加载（`vld1q` 不要求对齐），但对齐的数据仍然更快：

- 对齐到 64 字节（缓存行大小）：一次内存访问
- 未对齐：可能跨越两个缓存行，需要两次访问

在实际使用中，NumPy 数组默认对齐到 64 字节，所以使用 NumPy 输入的性能最优。

## 四、编译器优化协助

### 4.1 nonnull 属性：允许省略 NULL 检查

```c
// types.h 第 37-38 行
#define SIMSIMD_PUBLIC __attribute__((unused, nonnull)) inline static
//                                           ↑
// 告诉编译器：所有指针参数保证非 NULL
// 编译器可以省略生成的 NULL 检查代码
```

### 4.2 always_inline：消除函数调用开销

```c
#define SIMSIMD_INTERNAL __attribute__((always_inline)) inline static
//                                      ↑
// 强制内联，消除函数调用、参数传递、返回地址保存等开销
// 用于 reduce_u8x16、sqrt_f32 等频繁调用的小函数
```

### 4.3 restrict 指针：允许编译器优化别名

（SimSIMD 通过设计保证输入指针不重叠，虽然没有显式用 restrict，但 nonnull 配合函数设计已经给了编译器足够信息）

## 五、无 LibC 依赖的设计

`c/lib.c` 的顶部有重要的定义：

```c
// c/lib.c 第 12-14 行
// 覆盖基础数学函数，使用近似版本，避免 LibC 依赖
#define SIMSIMD_SQRT(x)  simsimd_approximate_square_root(x)
#define SIMSIMD_RSQRT(x) simsimd_approximate_inverse_square_root(x)
#define SIMSIMD_LOG(x)   simsimd_approximate_log(x)
```

**为什么避免 LibC？**

1. **嵌入式环境**：某些嵌入式系统没有完整的 LibC
2. **裸机环境**：操作系统内核、BootLoader 中不能用 LibC
3. **WebAssembly**：WASM 环境中 LibC 的 math.h 有额外开销
4. **精度选择**：近似版本的精度对相似度计算足够，但比 LibC 快

## 七、所有设计决策的汇总

### 7.1 "不做无用功"的原则

```
l2sq（平方欧氏距离）单独实现：
  l2(a, b) 先调用 l2sq，再开方
  l2sq 不开方，比 l2 快约 20%

余弦距离用 RSQRT 而不是 SQRT：
  1 - (ab × rsqrt(a2) × rsqrt(b2))  比
  1 - ab / (sqrt(a2) × sqrt(b2)) 少一次除法
```

### 7.2 "精度够用就行"的原则

```
默认 serial 实现用 f32 精度（比 f64 快2倍）：
  SIMSIMD_MAKE_COS(serial, f32, f32, ...)  ← f32 累加
  SIMSIMD_MAKE_COS(accurate, f32, f64, ...) ← f64 累加（高精度版本）

f16/bf16 输入升精度到 f32 累加（而非 f64）：
  性能与精度的最优平衡点
```

### 7.3 "一套代码，无限扩展"的原则

```c
// 一个宏，生成所有类型+所有后端的组合
SIMSIMD_MAKE_COS(serial,   f32,  f32,  SIMSIMD_DEREFERENCE)
SIMSIMD_MAKE_COS(serial,   f16,  f32,  SIMSIMD_F16_TO_F32)
SIMSIMD_MAKE_COS(serial,   i8,   i32,  SIMSIMD_DEREFERENCE)
SIMSIMD_MAKE_COS(accurate, f32,  f64,  SIMSIMD_DEREFERENCE)
// ...添加新类型只需一行！
```

### 7.4 "零开销抽象"的原则

```
头文件库 → 编译器看到全部代码，可以跨函数优化
强制内联（always_inline）→ 消除辅助函数调用开销
void* + static函数指针 → 运行时多态，仅第一次调用有查找开销
buffer protocol → 零拷贝，不做数据复制
```

## 九、设计模式总结

SimSIMD 使用了以下核心设计模式：

| 模式 | 体现 | 目的 |
|------|------|------|
| 策略模式 | 函数指针 + `find_kernel_punned` | 运行时选择算法 |
| 模板方法（宏实现）| `SIMSIMD_MAKE_*` 宏族 | 代码复用，一模板多类型 |
| 惰性初始化 | `static metric = 0` + 首次调用检测 | 延迟昂贵的CPU探测 |
| 类型擦除 | `void *` 函数指针 | 统一不同类型的接口 |
| 外观模式 | `simsimd.h` 聚合所有头文件 | 单一入口点 |
| 适配器模式 | Python/JS/Rust 绑定 | 统一 C 接口给各语言 |

## 十一、如何开始使用

### C 语言（头文件模式）

```c
#include "simsimd/simsimd.h"

float a[] = {1.0f, 2.0f, 3.0f};
float b[] = {4.0f, 5.0f, 6.0f};
simsimd_distance_t distance;

// 自动选择最优实现
simsimd_cos_f32_serial(a, b, 3, &distance);
printf("Cosine distance: %f\n", distance);
```

### Python

```python
import simsimd
import numpy as np

a = np.array([1.0, 2.0, 3.0], dtype=np.float32)
b = np.array([4.0, 5.0, 6.0], dtype=np.float32)

# 点距离
dist = simsimd.cosine(a, b)

# 矩阵对矩阵距离
A = np.random.randn(100, 128).astype(np.float32)
B = np.random.randn(200, 128).astype(np.float32)
distances = simsimd.cdist(A, B, "cos")  # 100×200 距离矩阵
```

### 查询 CPU 能力

```python
import simsimd
caps = simsimd.get_capabilities()
print(caps)
# {'serial': True, 'neon': True, 'sve': True, 'haswell': True, ...}
```
