# 分支消除、特殊情况优化与位操作技巧

> 本文是 SimSIMD 高性能编程讲解系列第十篇。讲解高性能代码中消除分支、识别特殊情况快速路径、以及利用位操作加速计算的实战技巧。

---

## 一、为什么分支是性能杀手？

### 1.1 分支预测失败的代价

现代 CPU 使用**流水线（Pipeline）**技术——在当前指令还没完成时，就预先取下一条指令来执行。对于分支（if/else），CPU 必须猜测：

```
执行 if 分支还是 else 分支？
```

如果猜错了（**分支预测失败，Branch Misprediction**），CPU 必须：
1. 丢弃流水线中已经预取的指令
2. 重新取正确的指令
3. 代价：约 **15-20 个时钟周期**的惩罚

### 1.2 SIMD 循环中的分支问题

```c
// 有分支的写法（低效）
for (i = 0; i < n; i++) {
    if (a[i] > 0 && b[i] > 0) {
        result += a[i] * log(a[i] / b[i]);
    }
    // 每次循环都有条件分支
    // 如果 a[i]/b[i] 交替大于/小于0，预测失败率高
}
```

## 二、算术替代分支：无分支条件加法

### 2.1 布尔值本质是整数

在 C 语言中，布尔表达式的结果是 `0` 或 `1`（整数）。利用这一点可以消除分支：

```c
// sparse.h 第 26-30 行（集合交集的双指针算法）
// 原始有分支版本：
if (a[i] == b[j]) { intersection++; i++; j++; }
else if (a[i] < b[j]) { i++; }
else { j++; }

// 无分支版本（SimSIMD 的实现）：
intersection_size += (ai == bj);  // 相等则加1，否则加0
i += (ai <= bj);                  // a 不大于 b 时推进 a
j += (ai >= bj);                  // a 不小于 b 时推进 b
```

**两种等价性证明**：

```
情况1：ai < bj
  intersection += (ai==bj) = 0  ✓
  i += (ai<=bj) = 1            ✓  推进 a
  j += (ai>=bj) = 0            ✓  b 不动

情况2：ai == bj
  intersection += (ai==bj) = 1  ✓
  i += (ai<=bj) = 1            ✓  推进 a
  j += (ai>=bj) = 1            ✓  推进 b

情况3：ai > bj
  intersection += (ai==bj) = 0  ✓
  i += (ai<=bj) = 0            ✓  a 不动
  j += (ai>=bj) = 1            ✓  推进 b
```

**性能提升**：消除了最坏情况下 50% 的分支预测失败。

### 2.2 条件选择：三元运算符

```c
// 有分支（可能产生条件跳转）
float result = (condition) ? val_true : val_false;

// 如果编译器不优化，等价于：
if (condition) result = val_true;
else result = val_false;
```

现代编译器通常会把三元运算符编译成 `cmov`（条件移动）指令，这是无分支的。但对于复杂条件，不保证。

**SIMD 中的无分支选择**：

```c
// x86：_mm256_blendv_ps（基于掩码无分支选择）
__m256 mask = _mm256_cmp_ps(a_vec, b_vec, _CMP_GT_OQ);  // 比较生成掩码
__m256 result = _mm256_blendv_ps(b_vec, a_vec, mask);   // 无分支条件选择

// 等价于：for 8个元素同时做：result = (a > b) ? a : b
```

## 三、掩码操作：SIMD 的条件处理利器

### 3.1 AVX512 的掩码寄存器

AVX512 引入了专门的掩码寄存器（k0~k7），可以让 SIMD 指令有条件地处理部分元素：

```c
// probability.h Skylake KL 散度实现（部分）

// 生成掩码：只对 a[i] > 0 且 b[i] > 0 的元素计算 log
__mmask16 nonzero_mask_a = _mm512_cmp_ps_mask(a_vec, epsilon_vec, _CMP_GE_OQ);
__mmask16 nonzero_mask_b = _mm512_cmp_ps_mask(b_vec, epsilon_vec, _CMP_GE_OQ);
__mmask16 nonzero_mask = nonzero_mask_a & nonzero_mask_b;

// 只对非零元素执行 FMA，其他元素保持不变（mask3 变体：目标是第三个操作数）
sum_vec = _mm512_mask3_fmadd_ps(a_vec, log_ratio_vec, sum_vec, nonzero_mask);
// 等价于：for 每个元素：if (nonzero_mask) sum += a * log_ratio
```

**这替代了**：
```c
for (i = 0; i < n; i++) {
    if (a[i] > 0 && b[i] > 0) {  // 分支！
        sum += a[i] * log(a[i] / b[i]);
    }
}
```

### 3.2 掩码加载：尾部处理的完美方案

```c
// binary.h 第 279-283 行（Ice Lake Hamming 距离，尾部处理）

// 生成掩码：前 n_words 位为1，其余为0
// _bzhi_u64：清除高于指定位置的所有位
__mmask64 mask = (__mmask64)_bzhi_u64(0xFFFFFFFFFFFFFFFF, n_words);

// maskz_loadu：只加载掩码对应的字节，其余填0
__m512i a_vec = _mm512_maskz_loadu_epi8(mask, a);
__m512i b_vec = _mm512_maskz_loadu_epi8(mask, b);

// 直接计算，不需要单独的尾部循环！
__m512i xor_count_vec = _mm512_popcnt_epi64(_mm512_xor_si512(a_vec, b_vec));
```

## 四、特殊情况的快速路径

### 4.1 加权求和的三种特殊情况

`elementwise.h` 中的 `wsum_f32_haswell`（第 307-344 行）展示了一个完整的特殊情况优化模式：

```c
SIMSIMD_PUBLIC void simsimd_wsum_f32_haswell(
    simsimd_f32_t const *a, simsimd_f32_t const *b, simsimd_size_t n,
    simsimd_distance_t alpha, simsimd_distance_t beta, simsimd_f32_t *result) {

    // ===== 快速路径 1：alpha=1 && beta=1，退化为简单加法 =====
    if (alpha == 1 && beta == 1) {
        // 避免2次乘法，只做加法（约2x 加速）
        simsimd_sum_f32_haswell(a, b, n, result);
        return;
    }
    // ===== 快速路径 2：有一个权重为0，退化为标量乘法 =====
    else if (alpha == 0 || beta == 0) {
        // 只需加载一个数组（少50%内存带宽）
        if (beta == 0) { simsimd_scale_f32_haswell(a, n, alpha, result); }
        else           { simsimd_scale_f32_haswell(b, n, beta,  result); }
        return;
    }

    // ===== 通用情况：两个权重都非零且非1 =====
    __m256 alpha_vec = _mm256_set1_ps((float)alpha);  // 广播标量到向量
    __m256 beta_vec  = _mm256_set1_ps((float)beta);

    simsimd_size_t i = 0;
    for (; i + 8 <= n; i += 8) {
        __m256 a_vec = _mm256_loadu_ps(a + i);
        __m256 b_vec = _mm256_loadu_ps(b + i);
        __m256 result_vec = _mm256_add_ps(
            _mm256_mul_ps(a_vec, alpha_vec),   // alpha * a
            _mm256_mul_ps(b_vec, beta_vec)     // beta * b
        );
        _mm256_storeu_ps(result + i, result_vec);
    }
    for (; i < n; ++i) result[i] = (float)alpha * a[i] + (float)beta * b[i];
}
```

**这个设计的价值**：

```
场景                     快速路径           节省的操作
alpha=1, beta=1          simple add         2次乘法 × N = 2N次乘法
alpha=0                  scale(b, beta)     N次加法 + N次加载a
alpha=1, beta=0          scale(a, alpha)    N次加法 + N次加载b
一般情况                  通用路径           无节省
```

### 4.2 余弦距离的零向量处理

```c
// spatial.h（SIMSIMD_MAKE_COS 宏展开后）
if (a2 == 0 && b2 == 0) {
    *result = 0;     // 两个零向量：距离定义为0（相同）
    return;
}
else if (ab == 0) {
    *result = 1;     // 点积为0（完全正交）：距离为1
    return;
}
else {
    // 正常计算
    simsimd_distance_t r = 1 - ab * SIMSIMD_RSQRT(a2) * SIMSIMD_RSQRT(b2);
    *result = r > 0 ? r : 0;  // 裁剪负值（数值误差）
}
```

**注意裁剪**：即使数学上余弦距离不会为负，由于 RSQRT 的近似误差，计算结果可能出现微小负数（如 -0.000001）。最后的 `r > 0 ? r : 0` 保证输出语义正确。

## 五、位操作技巧

### 5.1 bzhi：清零高位

```c
// _bzhi_u64(value, index) = 清零 value 中第 index 位及以上的所有位
// 等价于：value & ((1 << index) - 1)

// 用于生成 n_words 个1的掩码
__mmask64 mask = (__mmask64)_bzhi_u64(0xFFFFFFFFFFFFFFFF, n_words);

// n_words=3：mask = 0b...00000111 = 只有低3位为1
// _bzhi_u64(0xFF...FF, 3) = 0b...00000111
```

**用途**：在 AVX512 掩码加载中指定有效元素范围。

### 5.2 lzcnt：前导零计数（用于稀疏向量）

```c
// sparse.h 第 442-443 行
// _lzcnt_u32：计算32位整数的前导零个数（Leading Zero Count）

// 应用：从 SIMD 比较结果（掩码）确定下一个匹配位置
simsimd_size_t a_step = 32 - _lzcnt_u32((simsimd_u32_t)a_step_mask);
// 如果 a_step_mask = 0b00000000_00000000_00000000_00010000
// 则 _lzcnt_u32(mask) = 27（前27位是0）
// 32 - 27 = 5（第5位是1，说明需要跳5步）
a += a_step;  // 推进 a 指针
```

### 5.3 shrdi：拼接移位（用于稀疏交集）

```c
// sparse.h 第 294-297 行（Turin u16 交集）
// _mm512_shrdi_epi32：把两个 32 位寄存器拼接后右移

// 原理：[b0_hi, b0_lo | b1_hi, b1_lo | ...]（b 是 32 位，每个存 2 个 u16）
// shrdi(b, b, 16)：把 [b, b] 拼成 64 位，右移 16 位
// 结果：[b0_hi, b0_hi | b1_hi, b1_hi | ...]（高16位复制到低16位）
__m512i b01 = _mm512_shrdi_epi32(b, b, 16);
// 这样 b 和 b01 就包含了 u16 的两种排列，可以与 a 的两种排列做交叉比较
```

### 5.4 XOR 实现符号翻转（用于复数点积）

```c
// dot.h 第 928-950 行（复数点积的巧妙实现）

// 复数乘法展开：
// (ar + iai)(br + ibi) = (ar*br - ai*bi) + i(ar*bi + ai*br)

// 朴素实现：需要 shuffle（分离实虚部）+ FMA + FMS
// 代价：shuffle 指令延迟高，吞吐量低，结果只有 2.5 GB/s

// 优化实现：利用 XOR 翻转符号（注释原文）
// "to multiply a floating-point value by -1, we can use the XOR instruction
//  to flip the sign bit. This way we can avoid the shuffling."

__m256i sign_flip_vec = _mm256_set1_epi64x(0x8000000000000000);
// 0x8000000000000000 = 最高位为1，其余为0
// 这是 f32 中 -1.0 × 任意数 的效果：只翻转符号位

// 主循环中，不用 shuffle，直接同一个布局做两次 FMA
// 最后用 XOR 翻转需要取反的部分
ab_real_vec = _mm256_castsi256_ps(
    _mm256_xor_si256(_mm256_castps_si256(ab_real_vec), sign_flip_vec)
);
// 这种方法使吞吐量从 2.5 GB/s 翻倍到 5 GB/s！
```

**原理解析**：

```
在复数点积中，实部 = ar*br - ai*bi

优化思路：
  1. 计算 [ar*br, ai*bi, ar*br, ai*bi, ...] (交织存储的连续乘积)
  2. 用 XOR 翻转奇数位置的符号（ai*bi → -ai*bi）
  3. 用 hadd 把相邻对求和：ar*br + (-ai*bi) = ar*br - ai*bi ✓

这样就不需要把实部和虚部分开存储再分别处理！
```

## 六、内存访问的优化策略

### 6.1 对齐存储（elementwise.h 注释）

```c
// elementwise.h 第 224-228 行的注释（原文）：
// "Unlike the distance metrics, the SIMD implementation of FMA and WSum
//  benefits from aligned stores. Assuming the size of ZMM register matches
//  the width of the cache line, we skip the unaligned head and tail of the
//  output buffer, and only use aligned stores in the main loop."

// 实现思路：
size_t head = (64 - ((uintptr_t)result % 64)) % 64;  // 对齐前的字节数
// 用标量处理 head 个元素，直到 result 指针对齐到 64 字节
// 然后用对齐存储指令 _mm512_store_ps（比 storeu 快）
// 再用标量处理尾部
```

**为什么写操作需要对齐但读操作不需要？**

- **读**：现代 CPU 的非对齐读（`loadu`）在 L1 缓存命中时开销极小
- **写**：非对齐写可能跨越两个缓存行，需要两次"读-改-写"，代价更高
- AVX512 的 ZMM 寄存器（512位）= 一个缓存行（64字节），对齐时写一整个缓存行最高效

### 6.2 非对齐读的优化：lddqu

```c
// _mm256_lddqu_si256 vs _mm256_loadu_si256
// 两者语义相同，但 _lddqu 对跨缓存行的未对齐读有轻微优化

// dot.h 第 1157-1158 行：
__m256i a_i8_vec = _mm256_lddqu_si256((__m256i const *)(a_scalars + idx));
//                  ↑ 用 lddqu 而不是 loadu
```

在 Intel 手册中，`LDDQU` (Load Unaligned Integer 256 Bits) 专为可能跨缓存行的加载优化，在某些微架构上比 `VMOVDQU` 更高效。

### 6.3 预广播标量权重

```c
// 在循环外一次性广播，避免循环内重复广播
__m256 alpha_vec = _mm256_set1_ps(alpha_f32);  // 在循环外
__m256 beta_vec  = _mm256_set1_ps(beta_f32);   // 在循环外

for (i = 0; i + 8 <= n; i += 8) {
    // 直接使用，不需要每次广播
    _mm256_mul_ps(a_vec, alpha_vec);
}
```

如果 `_mm256_set1_ps` 在循环内，编译器可能不会优化，造成每次循环都执行一次广播（虽然很快，但还是额外开销）。

## 七、SVE 的自适应处理：svcntb()

```c
// binary.h 第 190-198 行（SVE Hamming，自适应宽度）
SIMSIMD_PUBLIC void simsimd_hamming_b8_sve(...) {
    // svcntb()：运行时返回 SVE 向量宽度（字节数）
    // 可能是 16（128位）、32（256位）、64（512位）等
    simsimd_size_t const words_per_register = svcntb();

    // 性能决策：如果 SVE 寄存器 ≤ 32 字节，用 NEON 可能一样快
    // （避免 SVE 的 predicate 寄存器开销）
    if (words_per_register <= 32) {
        simsimd_hamming_b8_neon(a, b, n_words, result);
        return;
    }
    // 否则使用 SVE 的更宽寄存器
    // ...
}
```

**这是"基于测量的决策"**：作者通过实测发现，在窄 SVE（128/256位）上，NEON 的表现不比 SVE 差甚至更好（因为 NEON 的 predicate 机制更简单）。这种运行时回退是非常实用的优化。

## 八、不要早期优化：保留文档中的次优方案

SimSIMD 的代码中保留了大量被注释掉的"朴素实现"（naive approaches），并注明了性能数据：

```c
// dot.h 第 898-925 行（复数点积，保留了朴素方案的注释）

// The naive approach would be to use FMA and FMS instructions on different
// parts of the vectors. Prior to that we would need to shuffle the input
// vectors to separate real and imaginary parts.
// Both operations are quite expensive, and the resulting kernel would run
// at 2.5 GB/s.
//
//  __m128 ab_real_vec = _mm_setzero_ps();
//  __m128 ab_imag_vec = _mm_setzero_ps();
//  for (...) {
//      __m256 a_shuffled = _mm256_permutevar8x32_ps(a_vec, permute_vec);
//      ...
//  }
//
// Instead, we take into account, that FMS is the same as FMA with a
// negative multiplier... Both operations are quite cheap, and the
// throughput doubles from 2.5 GB/s to 5 GB/s.
```

**为什么保留注释掉的代码？**

1. **文档价值**：未来维护者能理解"为什么不用更自然的方式"
2. **基准对比**：注明了 2.5 GB/s vs 5 GB/s，直接量化了优化效果
3. **防止退步**：避免未来有人"简化"代码时无意间引入性能退步

## 九、小结：分支消除的三大模式

```
模式1：用算术替代条件跳转
  before: if (a == b) count++; if (a < b) i++;
  after:  count += (a == b); i += (a <= b);
  原理：布尔值是0/1，可直接用于加法

模式2：用 SIMD 掩码替代逐元素分支
  before: for (...) { if (cond) do_something(); }
  after:  mask = compare(vec, threshold); masked_op(vec, mask);
  原理：SIMD 掩码指令无分支处理条件逻辑

模式3：特殊情况快速路径
  before: 总是走通用路径
  after:  if (alpha==1 && beta==1) → fast_add()
  原理：识别高频特殊情况，提供零开销路径

额外技巧：
  - 位操作（XOR 翻转符号，bzhi 生成掩码，lzcnt 找位置）
  - lddqu（更好的非对齐读）
  - 循环外预广播常量
  - SVE 自适应宽度回退
  - 保留注释掉的朴素实现以供参考
```
