# SimSIMD 二进制距离与概率距离实现详解

> 本文是 SimSIMD 讲解系列第四篇，深入解析 `binary.h` 中的 Hamming/Jaccard 距离，以及 `probability.h` 中的 KL 散度和 JS 散度。

## 一、二进制向量是什么？

在机器学习和信息检索中，**二进制向量（Bit Vector）**是一种极度压缩的表示形式：每个元素只用 1 个比特（0或1），把64个二进制特征打包进一个 64 位整数。

SimSIMD 使用 `simsimd_b8_t`（即 `uint8_t`）作为基本单位，每个 b8 存储 **8 个位**。

```
例如：两个 3 字节（24位）的二进制向量：
a = [11010011, 00110101, 10001001]
b = [10110011, 01010100, 11001001]
     ^^^^^^^^  ^^^^^^^^  ^^^^^^^^
     8 bits    8 bits    8 bits
```

## 二、Hamming 距离：数不同位的数量

### 2.1 数学定义

```
Hamming(a, b) = 两个向量中不同位的总数
             = popcount(a XOR b)
```

**XOR（异或）**：相同位为0，不同位为1。对 XOR 结果数 1 的个数（popcount），就得到 Hamming 距离。

```
例：
a[0] = 11010011 = 0xD3
b[0] = 10110011 = 0xB3

XOR  = 01100000 → popcount = 2（有2位不同）
```

### 2.2 Popcount 查找表（serial 实现）

```c
// binary.h 第 81-92 行
SIMSIMD_PUBLIC unsigned char simsimd_popcount_b8(simsimd_b8_t x) {
    // 256个条目的查找表，index=0~255，value=该数的位数
    static unsigned char lookup_table[] = {
        0, 1, 1, 2, 1, 2, 2, 3, 1, 2, 2, 3, 2, 3, 3, 4,  // 0~15
        1, 2, 2, 3, 2, 3, 3, 4, 2, 3, 3, 4, 3, 4, 4, 5,  // 16~31
        // ... 共256项
        4, 5, 5, 6, 5, 6, 6, 7, 5, 6, 6, 7, 6, 7, 7, 8}; // 240~255
    return lookup_table[x];
}
```

**查找表原理**：预计算好 0~255 中每个数字的二进制 1 的个数。

```c
// serial 实现：
SIMSIMD_PUBLIC void simsimd_hamming_b8_serial(
    simsimd_b8_t const *a,
    simsimd_b8_t const *b,
    simsimd_size_t n_words,
    simsimd_distance_t *result) {

    simsimd_u32_t differences = 0;
    for (simsimd_size_t i = 0; i != n_words; ++i)
        // a[i] ^ b[i]：找出不同的位
        // simsimd_popcount_b8(...)：数有多少个不同位
        differences += simsimd_popcount_b8(a[i] ^ b[i]);
    *result = differences;
}
```

**时间复杂度**：O(n)，每个字节一次查表。

## 三、Jaccard 距离：集合交集与并集

### 3.1 数学定义

```
Jaccard 相似度 = |A ∩ B| / |A ∪ B|
             = popcount(a AND b) / popcount(a OR b)

Jaccard 距离 = 1 - Jaccard 相似度
```

**集合论角度**：把每个比特视为集合的一个元素，1 表示"该元素在集合中"，0 表示不在。

```
例：
a = 11010011 → 集合 {0,1,4,6,7}（1在第0,1,4,6,7位）
b = 10110011 → 集合 {0,1,4,5,7}

AND = 10010011 → 交集 {0,1,4,7} → popcount = 4
OR  = 11110011 → 并集 {0,1,4,5,6,7} → popcount = 6

Jaccard 相似度 = 4/6 ≈ 0.667
Jaccard 距离  = 1 - 0.667 = 0.333
```

```c
// serial 实现
SIMSIMD_PUBLIC void simsimd_jaccard_b8_serial(...) {
    simsimd_u32_t intersection = 0, union_ = 0;
    for (simsimd_size_t i = 0; i != n_words; ++i) {
        intersection += simsimd_popcount_b8(a[i] & b[i]);  // AND 的1的个数 = 交集大小
        union_       += simsimd_popcount_b8(a[i] | b[i]);  // OR  的1的个数 = 并集大小
    }
    *result = (union_ != 0) ? 1 - (simsimd_f64_t)intersection / (simsimd_f64_t)union_ : 1;
}
```

当 `union_ == 0` 时（两个全零向量），返回 1（最大距离）。

## 四、NEON 加速：ARM 的位计数指令

### 4.1 vcntq_u8：ARM 的硬件 popcount

ARM NEON 有一个 `vcntq_u8` 指令，可以**同时**对 16 个字节计算 popcount：

```c
// binary.h 第 130-151 行
SIMSIMD_PUBLIC void simsimd_hamming_b8_neon(...) {
    simsimd_i32_t differences = 0;
    simsimd_size_t i = 0;

    // 外层循环：每次处理 16×31 = 496 个字节
    while (i + 16 <= n_words) {
        // 每个 uint8 累加器最多能存255
        // 每个字节最多8个不同位 → 31次循环 × 8 = 248 < 255
        uint8x16_t differences_cycle_vec = vdupq_n_u8(0);

        // 内层循环：31次（防止8位计数器溢出）
        for (simsimd_size_t cycle = 0; cycle < 31 && i + 16 <= n_words; ++cycle, i += 16) {
            uint8x16_t a_vec = vld1q_u8(a + i);      // 加载16字节
            uint8x16_t b_vec = vld1q_u8(b + i);      // 加载16字节
            // XOR 后，对每个字节计算 popcount
            uint8x16_t xor_count_vec = vcntq_u8(veorq_u8(a_vec, b_vec));
            // 累加
            differences_cycle_vec = vaddq_u8(differences_cycle_vec, xor_count_vec);
        }
        // 把16个字节累加器汇总成一个整数
        differences += _simsimd_reduce_u8x16_neon(differences_cycle_vec);
    }
    // 尾部处理
    for (; i != n_words; ++i)
        differences += simsimd_popcount_b8(a[i] ^ b[i]);
    *result = differences;
}
```

### 4.2 为什么内层循环最多31次？

每个 `uint8_t` 最大存 255，每个字节最多 8 个不同位。
- 31次 × 每次加最多8 = 248 < 255 ✓
- 32次 × 每次加最多8 = 256 → **溢出！**

这是一个精心设计的**溢出防护**：在数字溢出之前先汇总。

### 4.3 水平求和：_simsimd_reduce_u8x16_neon

```c
// binary.h 第 115-127 行
SIMSIMD_INTERNAL simsimd_u32_t _simsimd_reduce_u8x16_neon(uint8x16_t vec) {
    // 第1步：把16个uint8扩展成8个uint16（分高低各8个）
    uint16x8_t low_half  = vmovl_u8(vget_low_u8(vec));   // 扩展低8字节
    uint16x8_t high_half = vmovl_u8(vget_high_u8(vec));  // 扩展高8字节

    // 第2步：两个 uint16x8 相加
    uint16x8_t sum16 = vaddq_u16(low_half, high_half);

    // 第3步：相邻配对求和，从8个uint16变成4个uint32
    uint32x4_t sum32 = vpaddlq_u16(sum16);

    // 第4步：从4个uint32变成2个uint64
    uint64x2_t sum64 = vpaddlq_u32(sum32);

    // 第5步：最终水平求和
    simsimd_u32_t final_sum = vaddvq_u64(sum64);
    return final_sum;
}
```

这个"逐层归约"（Tree Reduction）的过程：

```
输入：[v0, v1, v2, ..., v15]  (16个uint8)

扩展：[v0, v1, v2, ..., v7]  (8个uint16 低半段)
      [v8, v9, v10,..., v15] (8个uint16 高半段)

相加：[v0+v8, v1+v9, ..., v7+v15] (8个uint16之和)

配对：[(v0+v8)+(v1+v9), ..., ] (4个uint32)

配对：[sum_lo, sum_hi] (2个uint64)

水平：sum_lo + sum_hi (1个uint32)
```

**这种树形归约比逐个累加快得多**，因为多个步骤可以在 CPU 流水线中并行执行。

## 五、SVE 的自适应处理

```c
// binary.h 第 190-198 行
SIMSIMD_PUBLIC void simsimd_hamming_b8_sve(...) {
    // 检查 SVE 寄存器宽度
    simsimd_size_t const words_per_register = svcntb();

    // 如果寄存器 ≤ 32 字节（256位），NEON 同样有效，退而使用 NEON
    if (words_per_register <= 32) {
        simsimd_hamming_b8_neon(a, b, n_words, result);
        return;
    }
    // 更宽的寄存器（如 64 字节）才用 SVE 特有优化
    // ...
}
```

**SVE 的独特之处**：`svcntb()` 在运行时返回 SVE 寄存器的实际字节数（从 16 到 256 字节不等）。同样的代码在不同 CPU 上自动适配不同宽度。

## 六、KL 散度：信息论中的"信息量差异"

### 6.1 数学定义

KL 散度（Kullback-Leibler Divergence）衡量概率分布 P 与 Q 的"不同程度"：

```
KL(P || Q) = Σᵢ P(i) × log(P(i) / Q(i))
```

**直觉理解**：如果真实分布是 P，用 Q 来编码数据时，额外需要多少比特？

**注意**：KL 散度不对称，`KL(P||Q) ≠ KL(Q||P)`。

### 6.2 数值稳定性：ε 的作用

```c
// probability.h 第 86-97 行 (KL 宏)
#define SIMSIMD_MAKE_KL(name, input_type, accumulator_type, load_and_convert, epsilon) \
    // ...
    d += ai * SIMSIMD_LOG((ai + epsilon) / (bi + epsilon));
```

问题：如果 `bi = 0`，`log(ai/bi) = log(∞) = ∞`，结果会爆炸！

解决方案：加一个极小值 `epsilon`（ε）：

```c
// types.h 中定义
#define SIMSIMD_F32_DIVISION_EPSILON (1e-7f)  // 极小正数，防除零

// 效果：
// 即使 bi = 0：log((ai + ε)/(0 + ε)) = log(ai/ε)，仍然有限
```

## 七、JS 散度：KL 散度的对称版本

### 7.1 数学定义

Jensen-Shannon 散度解决了 KL 散度不对称的问题：

```
JS(P || Q) = √[ (KL(P||M) + KL(Q||M)) / 2 ]

其中 M = (P + Q) / 2  ← 两个分布的"中间"分布
```

JS 散度是对称的：`JS(P||Q) = JS(Q||P)`，且总在 [0, 1] 之间。

### 7.2 代码实现

```c
// probability.h 第 99-113 行 (JS 宏)
#define SIMSIMD_MAKE_JS(name, input_type, accumulator_type, load_and_convert, epsilon) \
    // ...
    for (simsimd_size_t i = 0; i != n; ++i) {
        accumulator_type ai = load_and_convert(a + i);
        accumulator_type bi = load_and_convert(b + i);
        accumulator_type mi = (ai + bi) / 2;  // 中间分布 M[i]

        // KL(P||M) 的第 i 项：P[i] × log(P[i]/M[i])
        d += ai * SIMSIMD_LOG((ai + epsilon) / (mi + epsilon));

        // KL(Q||M) 的第 i 项：Q[i] × log(Q[i]/M[i])
        d += bi * SIMSIMD_LOG((bi + epsilon) / (mi + epsilon));
    }
    // 最终：√(d/2)，注意这里包含了开方
    simsimd_distance_t d_half = ((simsimd_distance_t)d / 2);
    *result = d_half > 0 ? SIMSIMD_SQRT(d_half) : 0;
```

## 八、向量化对数：SIMD Log 的实现

KL/JS 散度需要计算 `log(x)`，这是一个超越函数，没有硬件指令直接支持（不像加减乘除）。SimSIMD 用**多项式近似**实现快速对数：

```c
// probability.h 第 142-170 行：NEON 上的 log₂ 近似
SIMSIMD_PUBLIC float32x4_t _simsimd_log2_f32_neon(float32x4_t x) {

    // 第1步：提取 IEEE 754 浮点的指数部分
    // IEEE 754 f32：[sign(1位)][exponent(8位)][mantissa(23位)]
    int32x4_t i = vreinterpretq_s32_f32(x);  // 把 f32 当 i32 看（位操作）

    // 提取指数：右移23位，减去127（消除偏置）
    int32x4_t e = vsubq_s32(
        vshrq_n_s32(vandq_s32(i, vdupq_n_s32(0x7F800000)), 23),
        vdupq_n_s32(127)
    );
    float32x4_t e_float = vcvtq_f32_s32(e);  // 转为 f32

    // 第2步：提取尾数部分（mantissa），规范化到 [1, 2) 范围
    // 把指数位强制设为 127（即 1.0 的指数），保留尾数
    float32x4_t m = vreinterpretq_f32_s32(
        vorrq_s32(vandq_s32(i, vdupq_n_s32(0x007FFFFF)),  // 尾数
                  vdupq_n_s32(0x3F800000))                  // 指数=127
    );

    // 第3步：用多项式近似 log₂(m)，m 在 [1, 2) 范围
    // 使用 Horner's Method：p(m) = (...((c₄·m + c₃)·m + c₂)·m + c₁)·m + c₀
    float32x4_t p = vdupq_n_f32(-3.4436006e-2f);  // 最高次系数
    p = vmlaq_f32(vdupq_n_f32(3.1821337e-1f), m, p);
    p = vmlaq_f32(vdupq_n_f32(-1.2315303f),   m, p);
    p = vmlaq_f32(vdupq_n_f32(2.5988452f),    m, p);
    // ...

    // 第4步：log₂(x) = log₂(2ᵉ × m) = e + log₂(m)
    return vaddq_f32(e_float, p);
}
```

### Horner 方法解释

计算多项式 `p(m) = c₀ + c₁m + c₂m² + c₃m³ + c₄m⁴` 的高效方式：

```
普通方式：需要计算 m², m³, m⁴，共 4 次乘法 + 4 次加法

Horner 方法：p(m) = c₀ + m(c₁ + m(c₂ + m(c₃ + m·c₄)))
只需 4 次乘法 + 4 次加法，但无需单独计算高次幂！
```

```c
// 代码中从最高次开始：
p = c₄                         // p = c₄
p = c₃ + m × p               // p = c₃ + c₄·m
p = c₂ + m × p               // p = c₂ + c₃·m + c₄·m²
p = c₁ + m × p               // p = c₁ + c₂·m + c₃·m² + c₄·m³
// ...
```

**这比标准多项式求值少约一半的乘法运算。**

## 九、IEEE 754 浮点结构的利用

`_simsimd_log2_f32_neon` 中用到了一个精妙的技巧：**把浮点数当整数处理，直接提取指数**。

```
IEEE 754 单精度浮点（32位）的布局：
 31   30 ............. 23   22 ................ 0
[sign][  exponent(8位)    ][    mantissa(23位)    ]

值 = (-1)^sign × 2^(exponent-127) × (1 + mantissa/2²³)

所以：log₂(x) = (exponent - 127) + log₂(1 + mantissa/2²³)
              = (exponent - 127) + log₂(m)   其中 m = 1.mantissa ∈ [1, 2)
```

通过整数位操作提取指数，避免了复杂的浮点除法：

```c
// 提取指数字段（位23~30）并减去127
int32x4_t e = vsubq_s32(
    vshrq_n_s32(vandq_s32(i, vdupq_n_s32(0x7F800000)), 23),
    //                        ↑ 0x7F800000 = 0111 1111 1000 0000... (只保留指数位)
    vdupq_n_s32(127)
);
```

## 十、编译目标特化的代码

SimSIMD 中大量使用 `#pragma` 来为同一源文件中的不同函数指定不同编译目标：

```c
// 开启 NEON 编译选项（只对紧接着的函数生效）
#pragma GCC push_options
#pragma GCC target("arch=armv8.2-a+simd")
#pragma clang attribute push(__attribute__((target("arch=armv8.2-a+simd"))), apply_to = function)

// 这里的函数会用 NEON 指令编译
SIMSIMD_PUBLIC void simsimd_hamming_b8_neon(...) { ... }

// 恢复之前的编译选项
#pragma clang attribute pop
#pragma GCC pop_options
```

这意味着：在同一个 `.c`/`.h` 文件里，不同的函数可以用不同的 CPU 目标编译，互不干扰！

## 十一、总结：两类特殊距离的设计哲学

### 二进制距离（binary.h）

| 操作 | 核心技术 | 关键指令 |
|------|---------|---------|
| XOR | 找出不同位 | `veorq_u8`, `^` |
| AND | 找出共同1 | `vandq_u8`, `&` |
| OR | 找出所有1 | `vorrq_u8`, `\|` |
| POPCOUNT | 数1的个数 | `vcntq_u8`(NEON), `POPCNT`(x86) |
| 溢出防护 | 31次内层循环 | 避免 uint8 超过 255 |
| 树形归约 | 逐层扩展求和 | `vmovl_u8`, `vpaddlq_u16` |

### 概率距离（probability.h）

| 操作 | 核心技术 | 细节 |
|------|---------|------|
| KL 散度 | P·log(P/Q) | ε 防止除零 |
| JS 散度 | √((KL(P\|\|M)+KL(Q\|\|M))/2) | M=(P+Q)/2 |
| Log 计算 | IEEE 754 + Horner 多项式 | 无需 libm |
| 向量化 | 同时对4/8/16个元素计算 | 减少循环次数 |
